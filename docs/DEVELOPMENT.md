# AnimeLog 开发总纲

版本：范围修订，2026-10-10。用户已明确：两端独立、没有同步；AI 每次处理一部作品且只新建记录。

## 1. 使用方式

日常动作只有：添加一部作品、调整观看进度、查询与编辑记录、导出或导入 JSON。

AI 是添加作品的辅助工具。输入“作品名 + 可选季度 / 剧场版 / OVA”，确认资料后创建一条独立记录。程序读取同一作品的已有记录，符合条件时在草稿中建议下一刷；用户可修改建议。重刷仍然只创建新记录，增加确认后的刷次和标签。

第一版不实现批量自然语言输入、AI 更新进度、历史语言理解、由 AI 判断重刷、账号、远程业务后端或同步。保留本地程序的下一刷建议。2026-10-10 用户授权参照 AnimeTrack 增加本地观看总览与统计，纳入当前界面改造；图谱和漫画继续留到后续版本。设计与统计口径见 [界面与内容改造](UI_REDESIGN.md)。

## 3. 技术选型

| 部分 | 决定与理由 |
| --- | --- |
| UI | Flutter stable，Material 3，Android / Windows |
| 页面状态 | Flutter 内置 ChangeNotifier / Listenable + 每个功能的 Controller；第一版不引入额外状态管理框架 |
| 导航 | Flutter Navigator；路由只传记录 UUID，不传可变实体 |
| 数据库 | Drift + NativeDatabase / SQLite；类型化查询、显式迁移、后台 isolate 执行数据库操作 |
| HTTP | package:http；统一超时、取消及错误转换；通过适配器发送 OpenAI-compatible 请求 |
| AI Key | flutter_secure_storage；设置表只存接口地址和模型，Key 不进入 SQLite |
| 文件选择与导出 | file_picker + 平台 FileService，读取 / 写入字节，不依赖浏览器下载或假定 Android URI 是文件路径 |
| 数据身份 | uuid，随机 UUID v4；只服务本地身份、关系和备份去重 |
| 文件目录 | path_provider；数据库和缓存放应用私有目录，用户导出的文件放系统选择的位置 |

上述依赖现已接入，兼容版本固定在 pubspec.lock；Flutter / Dart 版本及两端实际检查见实现状态。后续调整依赖仍须核对实际 API 与平台要求，不凭旧文档写插件调用。

参考：[Drift 原生平台](https://drift.simonbinder.eu/platforms/vm/)、[http](https://pub.dev/packages/http)、[安全存储](https://pub.dev/packages/flutter_secure_storage)、[file_picker](https://pub.dev/packages/file_picker)、[uuid](https://pub.dev/packages/uuid)。

## 4. 简单分层

~~~text
features/ 页面、Controller
  → application/ 新建、手动进度、备份用例
  → core/domain/ 模型与规则
  → data/ SQLite Repository、HTTP、SourceProvider、FileService
~~~

依赖方向：application 依赖 core 中的接口，data 实现接口；只有应用组装处创建具体适配器。页面不写 SQL、HTTP 或平台文件操作。core 不依赖 Flutter。

不为每张表建立一套通用 CRUD 框架，不建立同步抽象、远程 Repository 或插件系统。创建入口只能调用创建接口；手动编辑使用单独用例。

建议目录：

~~~text
lib/
  core/ai/           提示词、响应 JSON、候选匹配
  core/domain/       独立记录、草稿、字段校验
  core/api/          小型用例接口
  application/       新建、手动进度、导入导出
  data/local/        Drift 表、迁移、Repository
  data/remote/       AI Client、Bangumi SourceProvider
  data/platform/     Key 与文件适配器
  features/          library、intake、detail、settings
~~~

## 5. 保存边界

识别、搜索、下载资料都在数据库事务外。用户看到可编辑草稿后点击保存，才开始一个短事务。

新建事务插入 anime 和 intake_commits；若表单填写总体备注，在同一事务中维护其结构化备注。draftId 唯一，重复点击或保存结果丢失后的重试返回首次记录。不能因同名已有记录改成 UPDATE，也不能在创建时生成观看历史。

刷次建议在用户确认前读取本机库计算，不调用 AI。先用来源 ID 匹配具体作品，来源不明的同标题记录须确认身份；有未完成记录时仅提醒，不默认升级刷次。保存使用草稿中已确认的次数，不在事务里重新算成另一个值。导入恢复不触发新建建议。

封面缓存失败只回退远程图片，不回滚已保存记录。只有保存成功才提示成功；应用关闭或返回后保留未提交草稿。保存途中禁止重复提交，旧网络请求返回时不能覆盖用户后来输入的新作品名。

详情编辑和进度加一使用独立事务。备份恢复先完整校验，再执行事务；这些接口不接收 AI 解析结果。

## 6. 网络与 AI

一次标题识别最多一次 AI 请求；候选选择最多一次 AI 请求，唯一严格匹配可跳过后者。取消操作终止当前 HTTP Client / request scope；普通错误不自动反复请求模型。

建议初始预算：AI 单次 20 秒、资料请求 10 秒、整条识别链路 45 秒，后续请求使用剩余预算。网络层统一区分无配置、超时、断网、认证失败、限流、无效响应及资料源失败。

接口地址约定为服务 base URL；适配器追加 chat/completions，规范化尾斜杠，兼容已经包含 /v1 的地址，不任意重复拼接。默认使用 HTTPS；用户明确配置的本地 HTTP 接口可用。日志不记录 Authorization、Key 或完整 AI 请求响应。

第一版使用非流式响应。AI 失败可重试识别或切换手动添加；Bangumi 失败仍可保存只有标题的记录。

SourceProvider 统一字段命名和单位，来源的未知 / 零总集数映射为 null；作品形式不能从候选顺序推测。它只返回资料，不填充个人状态、进度、评分或标签。

## 7. 两端体验

- Android：系统返回键先处理弹窗或未保存表单；软键盘不遮挡保存；导入导出通过系统选择器；旋转或进后台保留输入草稿。
- Windows：Tab 焦点顺序、Enter 搜索、Ctrl+Enter 确认可用；窗口缩小时仍能完成录入；导出使用系统保存对话框。
- 两端均支持中文输入、文字缩放、空状态、网络失败及离线编辑。
- 新安装建立独立本地数据库；覆盖升级保留数据库、Key 和未保存草稿。卸载会删除私有数据，恢复依赖用户导出的 JSON。

1. 生成 Flutter 工程，确定 applicationId；两端验证 SQLite、安全存储和原生 JSON 文件读写。
2. 实现离线手动添加 → 列表 → 详情 → 关闭重开，验证持久性。
3. 实现进度加一、普通表单编辑和历史纠正，验证事务回滚。

5. 接入单部 AI 识别、真实候选和确认后新建；普通和重刷共用创建流程。
6. 按验收清单进行 Android 真机与 Windows 测试，再制作正式包。
