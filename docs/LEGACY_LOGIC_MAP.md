# AnimeTrack → AnimeLog 迁移地图

旧项目：D:/Projects/AnimeTrack。新规格采用用户实际用法，旧项目的行为不是必须逐项保持的标准。

## 1. 保留、重写、移除

| 旧内容 | 处理 | 当前状态 |
| --- | --- | --- |
| 中文数字、季数提取 | 保留纯文本工具 | core 中已有，严格匹配保留作品身份标点 |
| AI JSON 提取 | 保留响应清洗 | 已有，不负责数据库写入 |
| 真实候选 ID 选择 | 保留并增加形式约束 | core 规则及 HTTP / SourceProvider 已接入；候选 AI 只接收实际前 20 个候选，用户确认后新建 |
| 批量作品 / 批量季度 | 移除 | 新协议只接受 record |
| 自然语言观看进度、状态和日期 | 移除 | AI 模型不含这些字段 |
| AI 更新已有作品 | 移除 | 创建 Repository 只有新建方法 |
| 根据已有记录建议下一刷 | 保留并收紧身份与完成状态条件 | core 已有纯 Dart 规则，不增加 AI 请求 |
| 根据自然语言进度推断重看意图 | 移除 | 创建入口只接受作品身份；次数在草稿确认 |
| 新建时补观看历史 | 移除 | 新建不生成历史；手动操作另行记录 |
| SQLite 事务与历史维护 | 按手动动作重写 | 已实现本地 Drift Repository、新建幂等、手动进度/历史、即时撤销、级联删除和 JSON 导入事务 |
| Bangumi 搜索 / 详情 | 重写 SourceProvider | 已实现 v0 搜索与按 ID 详情；真实公开查询通过，形式 / 正片话数 / 未知值独立映射 |
| JSON 导入导出 | 兼容旧格式并建立新格式 | 已实现 AnimeLog v1 往返、恢复快照、追加 UUID 去重和 AnimeTrack v5 转换；系统选择器/真机验收待完成 |
| Web 页面、NextAuth、MCP、服务器管理 | 不迁移 | 新应用没有这些依赖 |

当前核心检查验证新的单部新建规则，数据库事务已有集成验证；Windows 安全存储和本机 HTTP fixture 页面闭环已通过。AI 真实模型识别效果及 Android 插件仍需后续验证；不以旧 TypeScript 全量行为的等价移植为目标。

## 2. 旧数据与旧规则分别处理

删除旧 AI 功能不等于丢弃旧个人数据。旧动漫记录、评分、标签、进度、备注及实际历史按 BACKUP.md 的兼容适配器保留。

旧二刷、三刷标签可以映射成 rewatchCount，不基于同标题记录数量重算。没有明确刷次的重温标签保留原标签，交给用户手动修正。

旧数据中的字段别名、嵌套总体 / 分集备注、整型 ID 关系由独立 LegacyBackupAdapter 转换，不能直接复制旧数据库文件到新应用。

## 3. 禁止继续沿用的旧入口

AnimeTrack 的 /api/anime/quick-record 会解析并直接修改服务器数据库。AnimeLog 不调用该路由，不保留更新结果、批量部分成功或流式保存事件。

不能为“兼容旧代码”把 ParsedQuickRecordBatch、resolveTargetProgress、shouldAutoResolveRewatch、全局季度拆分或语言历史兜底再加回创建流程。保留的是本地的下一刷建议，不是旧的观看意图解析分支。

## 4. 迁移完成的判断

- 单个名字可以生成一条新建草稿。
- 加季度、剧场版、OVA 限定后候选仍是该具体条目。
- 同名已有记录不变，用户确认后产生新的 UUID。
- 普通 / 重刷的差别只有显式次数与派生标签；新建都不增加历史。
- 旧 JSON 的进度、备注、历史和关联关系迁移正确。
- 无 AI / 无网络时手动创建与编辑可用。
