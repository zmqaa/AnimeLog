# AnimeLog 领域模型与数据结构

版本：独立记录与手动进度，2026-10-10。

当前状态：六张表、独立记录、总体备注事务、手动进度/历史及 JSON 迁移均已实现。数据库为 v3，迁移保留记录、关系、提交凭据和设置；允许开始日期存在但来源为空，以保留旧数据中的不确定来源，这类日期不被历史纠正覆盖。现已接入分集备注编辑、降低进度时的可选批量历史清理、撤销历史时同步回退进度，以及已有记录只补缺失资料的独立用例；不需要新增表或升级 schema。实际检查见 [实现状态](IMPLEMENTATION_STATUS.md)。

## 1. 第一版模型

一条 AnimeRecord 表示一条独立的个人动漫记录。普通记录和二刷、三刷记录均保存自己的进度、评分、备注、日期和历史。

第一版只用一张 anime 表存作品资料和个人字段；Dart 中用 AnimeMetadata 区分作品资料。不单独建立作品库、观看轮次系统或跨记录共享更新机制。相同 sourceProvider + sourceId 可标识同一外部作品，但不能作为个人记录的唯一键。

## 2. AnimeRecord

| 字段 | 含义 |
| --- | --- |
| id | SQLite 内部整数主键，不导出作关系身份 |
| uuid | 随机 UUID v4，UNIQUE；JSON 往返保持不变 |
| title / originalTitle | 展示标题 / 可空原名 |
| season / entryType | 可空季度；tv、movie、ova、ona、special 或空 |
| sourceProvider / sourceId | 可空资料来源与条目 ID，成对存在 |
| status | watching / completed / dropped / plan_to_watch |
| progress | 当前进度，非负整数；零是有效值 |
| totalEpisodes / durationMinutes | 可空正整数 |
| score | 可空有限数字，0–10，不能把 0 当作未评分 |
| rewatchCount | 普通记录为空；重刷为 >=2 的整数，程序可建议下一刷，用户确认后保存 |
| tags | 用户标签加派生重刷标签；次数以 rewatchCount 为准 |
| notes | 可空总体备注 |
| summary / coverUrl / premiereDate / isFinished | 可空源数据资料 |
| localCoverPath | 本机缓存路径，不进入 JSON |
| startDate / endDate | 可空日历日期，不从创建时间猜观看日期 |
| startDateSource | manual / history / null；保护用户手动日期不被历史纠正覆盖 |
| createdAt / updatedAt | 完整 UTC ISO 时间 |

同名记录合法，同来源记录合法；一刷与重刷互不修改。用户修改重刷次数时重新生成标签；普通记录移除重刷次数及保留的数字刷标签。

新增草稿前可按来源组合读取已有记录，由纯 Dart 规则建议下一刷；来源不明时确认完整标题身份，未完成的记录不默认触发重刷。次数以最高明确字段 / 旧刷次标签为依据，不从记录条数推断。导入只恢复原次数，具体规则见 AI_INTAKE.md。

## 3. 观看历史与备注

watch_history：

- id：内部主键；uuid：稳定导出身份。
- animeUuid：关联个人记录 UUID，外键 ON DELETE CASCADE。
- episode：正整数。
- watchedOn：用户确认的 YYYY-MM-DD 日历日期。
- watchedAt：可空 UTC ISO 时间；只有实际知道时刻时保存。
- createdAt：事件录入时间，与观看时间分别保存。

没有日期的旧观看意图不生成假的今天事件。日期已知而时刻未知时，只保存 watchedOn。合法的同一集再次观看允许多条历史，不按“作品 + 集数 + 日期”建立唯一索引。

anime_notes 用 uuid、animeUuid、episode（可空）、content、notedOn、createdAt、updatedAt。episode 为空表示总体备注；总体备注在 UI 是一个字段，存储时与 anime.notes 在同一事务中保持一致。详情页支持分集备注新增、编辑和逐条确认删除。同一集可以有多条备注，备注集数须为正整数，不推算观看进度或历史；编辑保持 UUID 与创建时刻，只修改明确填写的集数、内容和备注日期。分集接口校验所属记录，不允许操作总体备注或其他记录的备注。

## 4. 手动进度行为

| 操作 | 进度变化 | 历史变化 |
| --- | --- | --- |
| 新建作品 | 默认 0，表单可显式填写已有进度 | 不自动生成历史 |
| 列表点击 +1 | 从事务内当前值增加 1 | 只记录这次新增集，默认今天，可改日期 |
| 列表 / 详情点击 −1 | 当前进度减 1 | 同一事务删除高于新进度的观看历史 |
| 详情修改进度 | 设为明确值，可清零或降低 | 默认保留历史，不推算期间观看日期 |
| 显式记录第 N 集 | 进度取当前值与 N 的较大值 | 仅追加第 N 集事件 |
| 手动标记看完 | 已知总集数时设为总集数；未知时保留明确进度 | 不自动给整部补今天历史 |
| 纠正一条历史 | 保持进度 | 只修改选定事件 |
| 撤销一条历史 | 回退到当前进度与该集数减一的较小值 | 同一事务删除高于回退后进度的全部历史 |
| 删除动漫记录 | 删除记录 | 级联删除其历史和备注 |

若手动降低进度，编辑页提供“同时删除高于新进度的观看历史”，默认关闭，保存前展示删除数量并再次确认。数据管理或详情页撤销一集时，进度回退到当前进度与该集数减一的较小值，并在同一事务删除所有高于新进度的历史。两类批量删除均预览 UUID、目标进度、父记录版本和具体历史集合；事务中重新核对，数量相同但内容变化也拒绝旧确认。表单编辑、总体备注及历史清理在同一事务中完成；高于进度的分集备注保留。历史来源的开始日期重新计算，手动或来源未知日期受到保护；用户在同一表单明确清空开始日期时也保留空值。历史与进度的联动只发生在明确回退 / 撤销操作中。

+1 达到已知总集数时转为 completed；到顶后禁用 +1。标记看完可由用户填写完成日期，默认不虚构日期。修改进度使 completed 记录低于已知总集数时改为 watching，清除完成日期；总集数未知时由用户选择状态。

开始日期若由最早的已知历史推得，需要记录 startDateSource=history；手动填写则为 manual。纠正历史只重新计算 history 来源的日期，不覆盖手动日期。

进度 +1 保存成功后短暂提供撤销，仅针对刚刚这次操作。撤销在事务中恢复该次进度变化并删除它新增的事件；有后续进度 / 历史操作时不再提供此入口，当前进度或关联事件不符合回执时也不能强行撤销。其他纠错仍通过详情页完成，不建立通用撤销系统。

删除动漫前展示该条记录及将级联删除的历史、备注数量，确认后才执行；同作品的其他刷次记录不受影响。

## 5. SQLite 约束

初始表为 anime、watch_history、anime_notes、app_settings、intake_commits，以及 legacy_imports（旧备份去重凭据）。

- anime.uuid、历史 uuid、备注 uuid 建唯一索引。
- anime 上给 status、updatedAt、title、sourceProvider + sourceId 建普通索引；来源组合不唯一。
- 数值范围、合法状态、来源字段成对、日期顺序在用例中校验；数据库同时设置能表达的 CHECK 与外键。
- 每个连接启用 foreign_keys；进度操作、创建凭据和导入使用事务。
- intake_commits 的 draftId 是主键，animeUuid 为外键；删除记录时级联清理对应凭据。
- schema 版本使用 Drift schemaVersion / migrationStrategy 与 SQLite user_version，不重复维护另一套版本表。
- app_settings 只存模型、接口地址和 UI 偏好。API Key 只在安全存储。

所有升级都写显式迁移并验证旧数据库数据保留，不启动时删表重建。缓存与数据库路径放平台适配层，不放领域模型校验代码。

## 6. 时间与字段修改

日历日期固定 YYYY-MM-DD，时间戳固定 UTC ISO；用户明确的 watchedOn 不随设备时区改变。createdAt 不能被当作 startDate。

完整表单保存可以把可空字段清成 null；禁止用“新值为空就保留旧值”实现用户编辑。资料补全使用详情页的独立用例：有 Bangumi 来源 ID 时读取同一条目，否则查询候选并由用户选择；预览空缺字段后确认，只写外部资料。标题、已有字段、false 完结值及个人状态、进度、评分、刷次、标签、备注和日期均保留。来源总集数与已有进度、完成状态或保留历史冲突时跳过该字段并提示；预览后记录变化会拒绝提交并要求重新预览。该用例没有 AI Client 或新建 Repository。

本项目不设计同步；没有 deviceId、revision、deletedAt 或 updatedBy。UUID 只解决 JSON 重复导入和跨文件外键映射。
